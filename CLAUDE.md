# Party Box – Arbeitsnotizen für Claude

Party-Spiele-App von Sascha. **Die App ist eine einzige Datei: `index.html`** (Vanilla JS, kein Build, keine Frameworks), läuft auf GitHub Pages. Nicht aufteilen, solange Sascha es nicht ausdrücklich sagt. Daneben liegen nur die PWA-Dateien (von Sascha ausdrücklich erlaubt): `manifest.webmanifest`, `sw.js`, Icons (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`, `favicon-32.png`). Antworten auf Deutsch, knapp, ehrlich; Annahmen und Unsicherheit offen nennen.

## Aufbau von index.html

1. `<style>` (CSS, Themes über `body[data-theme]`: feuer/neon/ozean; `body.calm` = Animationen aus)
2. Body: `#app` (Spiel), `#hw` (Host-Overlay "Gerade dran"), `#lv` (Client: Lobby verlassen), `canvas#fx`
3. Zwei eingebettete Bibliotheken: PeerJS (minifiziert, 1 Zeile) und qrcode-generator. **Nicht verändern.** Zum Lesen/Suchen nur mit `grep`/Offset, nie ganz ins Fenster laden.
4. Letztes `<script>` = die App, in dieser Reihenfolge (Abschnitte per `/* ===== … ===== */` markiert):
   core (Hilfsfunktionen, Config, Verlauf, Haptik/Ton, Effekte) → Fragen `Q` + Generatoren `GEN` → Wortlisten `PW`, Twists `TW` → UI (Home, Spieler, Einstellungen, Setup, Glücksrad, Session, `plan`, `hand`, `boardHTML`, `finish`) → Spiele (`arsch`, `pant`, `spy`, `wave`, `bluff`, `react`, `bomb`, `c4`, `most`, `taboo`, `hilo`, `never`, `kings`, dazu Kategorien/Startseite/Trink-Infrastruktur) → Online (`net`, Host, Client).

## Globale Zustände

| Name | Inhalt |
|---|---|
| `C` | Config `{days, fx, vib, sound, theme}`, gespeichert in `pb_cfg` (zusammen mit Namen) |
| `S` | `names`, `mode` ('solo'/'team'), `nt`, `P` (Spielernamen der laufenden Session), `tm` (Teams) |
| `G` | laufende Session (`id, def, o, team, ents, pts, …` plus Spiel-Felder) |
| `OPT` | Optionen pro Spiel (`OPT.arsch.rounds` …) |
| `CUR` | aktuelle Spiel-ID, `TH` = Farbverlauf des Spiels |
| `NET` | Online-Zustand (`on, host, client, code, m[], inGame, scr, peer, conn, perm, idx, localNames, syn`) |
| `ACT`, `PERM`, `WAIT` | Online: wer sieht/bedient gerade (siehe unten) |

## Spiele

Jedes Spiel ist `GAMES.<id>={name,e,tag,c,min,teams,desc,rules,opts(),start()}` (optional `nt2`). Screens kommen aus `scr(html)` (Template-Strings, Inline-`onclick`). Reihum-Spiele nutzen `hand(spielerIndex, nachricht, weiter, fortschrittHTML, tag)`: lokal der "Gerät weitergeben"-Screen, online siehe unten. `G.ents` sind Einzelspieler oder Teams, Punkte immer in `G.pts[eOf(i)]`. Ende mit `finish({asc,unit,vals,extra})`. Rundenplan für Teams: `plan(rounds)`.

**Wiederholungssperre:** `ordered(liste, keyFn, ns)` + `mark(ns,key)`, localStorage `pb_h_<ns>`. Namespaces in `HNS`: q (Fragen), w (Wörter), l (Orte), s (Skalen), b (Bluff), c (Bombe-Kategorien). Neuer Namespace → in `HNS` eintragen (sonst greift "Verlauf zurücksetzen" nicht).

## Online-Modus (PeerJS-Cloud, kein eigener Server)

- Spiel läuft **nur auf dem Host**. Clients bekommen eine DOM-Spiegelung von `#app` (MutationObserver, Elemente per `data-n`-ID). Pakete Host→Client: `full`, `mut` (ops `h`=innerHTML, `a`=Attribut), `wait`, `perm`, `fx` (confetti/flash/vib/sfx). Clients→Host: `hi`, `ev` mit `ty` = click | in | key | pointerdown/move/up/cancel | hb.
- Der Host führt Client-Events am echten DOM aus (`el.click()`, synthetische `PointerEvent`s, `NET.syn=true`). Es wird **kein Code von Clients ausgeführt**; Client-HTML wird beim Einsetzen von `on*`-Attributen befreit (`strip`, → `data-h-*`).
- `ACT` = Spielerindex, dessen Gerät den privaten Screen sieht (gesetzt vom `hand()`-Wrapper). Alle anderen bekommen `WAIT` ("Gerade dran"), der Host sieht dann das Overlay `#hw`. Private Inhalte (Schätzungen, Karten, Antworten) dürfen nur in Screens stehen, die nach `hand()` erzeugt werden.
- `PERM` regelt, wer auf **öffentlichen** Screens bedienen darf: `'host'` (Standard), `'all'`, Spielerindex oder Funktion. Festgelegt in `PUBW` (Liste der Funktionen, die `ACT=null` setzen und Views synchronisieren) und `PERMS` (Ausnahmen, z. B. `spyTalk`/`waGuess` = alle, `spyGuess` = Spion, `boLight` = Halter, `c4Round` = Spieler am Zug).
- **Neues Spiel:** jede Funktion, die einen öffentlichen Screen aufbaut (Ergebnis, Abstimmung, Rundenstart …), in `PUBW` eintragen, bei Bedarf Recht in `PERMS`. Sonst bleibt `ACT` vom letzten privaten Screen hängen.
- **Parallele Eingaben (Online-Host, `PAR`):** Statt Reihum (`hand`) bekommt jedes Gerät gleichzeitig einen eigenen Screen. `parBegin({head,msg,steps,done})` zeigt öffentlich nur den Stand (✅/⏳), jeder Schritt `{k,html(pi),sub(pi,{v,f})}` rendert das private Formular (Packet `own`; beim Host im Overlay `#hw`). Buttons tragen `data-sub`/`data-v`, Felder `data-f`, der Container `data-p` (Spielerindex). Clients schicken Daten `{ty:'sub',p,k,v,f}`, keine DOM-Klicks; der Host prüft in `parSub` (Gerät gehört zu `p`, Schritt passt) und `sub()` validiert und gibt `true` oder eine Fehlermeldung zurück. Getrennte Spieler: ihr Formular zeigt der Host, nach Wiederbeitritt bekommt sie wieder ihr Gerät. Genutzt von Arschkarte (`arPar`), Bluff (`bPar`/`bVotePar`) und Spion (`spyPar`); lokal bleibt alles Reihum. `PAR` wird in `wrapPub`, `lobbyScreen`, `netStop` zurückgesetzt.
- **Fragezeichen/Info (Arschkarte):** `qInfo(q)` = `q[3]` (generierte Fragen) oder `INFO[Fragetext]` (feste Fragen); Lookup-Tabellen `CITYI`, `MI` (Berge/Gebäude), `EVI` (Ereignisse), `PEOPLEI` für die Generatoren. `qBtn`/`qBox` bauen den "?"-Knopf und die verborgene Infobox in die Frageseite (lokal `arGuess`, online `arPar`); das Auf-/Zuklappen läuft rein lokal auf dem jeweiligen Gerät (`data-tg="qi"`). **Regeln für neue Infos:** erklären, was/wer gemeint ist, **keine Zahl nennen, die die Antwort ist** (Test prüft das); neue Personen/Städte/Ereignisse/Berge brauchen einen Eintrag in der passenden Tabelle. Ohne Info erscheint kein "?".
- **Bluff:** `OPT.bluff.timer` (0 = aus, Standard 60 s) = Schreibzeit, Abstimmzeit fest `BVOTE_MS` (20 s). Lokal: `bTimeUp` (eine getippte, gültige Antwort zählt, sonst keine Fälschung) und `bVoteUp` (`G.votes[i]=null` = keine Stimme); online über `parBegin({dur})` wie bei Arschkarte. `bResult` überspringt `null`-Stimmen und nennt Spieler ohne Antwort/Stimme. Info-Texte: `BQI` (Schlüssel = Antwort-Text), `qInfo` greift auf `q[3]`, `INFO[Frage]` oder `BQI[Antwort]` zu; die Info darf die Antwort und Wörter daraus nicht enthalten (Test prüft das).
- **Bluff-Fragenarten:** `BPOOL` = Wissen (`BQ`), Zitate (`BQZ`: „Vervollständige das Zitat: …“, Antwort = fehlendes Wort) und Wörter (`BQW`: „Was bedeutet das Wort …“ + kurze Erklärung); Chips `OPT.bluff.cats` (nichts gewählt = alle, `bStart` zieht reihum aus den gewählten Arten). Zitate sind aus dem Gedächtnis geschrieben, ohne Autorenangabe – bei Zweifeln an Echtheit prüfen. **Regel für neue Zitate:** Das fehlende Wort darf sich nicht allein aus dem Satz ergeben (kein „Ein Leben ohne Mops ist möglich, aber …“ → sinnlos); die Lücke soll die überraschende Pointe sein, bei der viele Antworten passen.
- **Reflex online:** Das Gerät des Spielers misst selbst ab dem Moment, in dem es Grün zeigt (`rxWatch`, Capture-Handler auf `#rx` fängt den Tipp ab) und schickt `{ty:'rx',k:'ms'|'early'}`; `rxRemote` auf dem Host prüft Gerät/Zustand und begrenzt die Zeit auf 80 ms … seit dem Start vergangene Zeit (ein manipuliertes Gerät kann also nur innerhalb dieser Grenzen schummeln). Ältere Clients ohne diese Logik werden weiter am Host gemessen.
- **Arschkarte-Wertung:** `arErr`/`arDiffTxt`: Jahreszahlen (Einheit `Jahr`) und negative Antworten absolut (Anzeige "39 Jahre daneben"), sonst Verhältnis über den Logarithmus (zu hoch/zu niedrig gleich schlimm, Anzeige "Faktor 3,3 zu niedrig" bzw. "10 % zu hoch"); Schätzung ≤ 0 bei positiver Antwort = schlechtester Wert.
- **Wellenlänge online:** `waGuess` zeigt statt "Einloggen" "Ich stimme zu" (`waAgree`); alle Rater (`G.gu`, ohne Hinweisgeber, nur verbundene Geräte) müssen zustimmen, ein verschobener Marker setzt alle zurück (`waMark`). Wer geklickt hat, steht in `NET.who` (wird in `netEvent` für die Dauer der synthetischen Aktion gesetzt; Host = null → 0).
- **Wellenlänge, Bonus online:** Beim Team-Bonus ("links oder rechts?") tippen die verbundenen Mitglieder des **entscheidenden Teams** (`G.tm[G.ot]`) selbst (`waSide`, Wahl pro Person in `G.lr`, Wer geklickt hat steht in `NET.who`); erst wenn alle dieselbe Seite gewählt haben, folgt `waReveal`. Uneinig → Hinweis "Noch nicht einig". `waLock` hat `PERMS` = `'all'`. Lokal (ein Gerät) entscheidet wie bisher der erste Tipp.
- **Bombe, "Falsch / schon genannt":** `boPass` merkt den Vorgänger (`G.bst`, inkl. Team-Zeiger `G.ht`/`G.hix`), `boBack` (Knopf `#bk`, Taste `F`) schickt die Bombe zurück, der Vorgänger muss ein neues Wort sagen; die Zündschnur läuft weiter. Online darf nur der aktuelle Halter drücken (`PERMS.boLight` = `G.hold`).
- **Spion online:** `spyVote` → `spyVotePar`: geheime parallele Abstimmung (30 s), `spyTally`: eindeutig meiste Stimmen = Beschuldigter, Gleichstand/keine Stimmen = Spion kommt davon (`spyEnd('tie')`), Stimmenverteilung steht in der Auflösung (`G.cnt`).
- **Namen:** Standardnamen `Spieler N` stehen nur als Platzhalter in den Feldern (nicht als Wert); sie werden nicht in der Statistik gezählt und nicht als Online-Name vorbelegt.
- **Version/Update:** `APP_VERSION` (Format `JJJJ-MM-TT.n`) **bei jeder Auslieferung erhöhen**. Einstellungen → "Auf Update prüfen" lädt die Seite mit `cache:'no-store'`, vergleicht die Version und lädt auf Wunsch neu (`applyUpdate`). Fragen stecken in `index.html`; ein Update der Fragen ist immer ein neuer Push (keine Nachlade-Datei).
- **Wer würde am ehesten (`most`, min 3):** Aussagen in `MQ` (3 Kategorien, Chips in `OPT.most.cats`). Lokal reihum geheim (`moVote`, `hand`), online parallel (`moPar`, ein Schritt `v` mit `dur`); Man darf auch für sich selbst stimmen (Eintrag „(ich)"); `moResult` deckt auf (Stimmen, wer wen gewählt hat), Wer für den/die Meistgewählten gestimmt hat, bekommt +1. `moFinish` zeigt "Meiste Stimmen des Abends"; Statistik-Zusatzwerte `gewaehlt`/`stimmen`.
- **Tabu (`taboo`, min 2, Teams):** Karten `TBS` (`'Begriff|v1|v2|v3|v4|v5'`, 4 Kategorien); Ablauf nach Vorbild Pantomime (`tHand` → `hand` → `tPlay`, Ring-Timer, `tOk`/`tTabu`/`tSkip`, `tEnd` in `PUBW`). Auftrittswert = max(0, Treffer − Tabus) für den Erklärer bzw. das Team, im Einzelmodus +1 für den Rater (`tPick`). Online nur der Erklärer sieht die Karte (wie Pantomime). Neue Karten: genau 5 verbotene Wörter, Begriff nicht selbst verboten, keine doppelten Begriffe (Test prüft das).
- **Mehr oder weniger (`hilo`, min 2):** Duelle werden aus vorhandenen Listen erzeugt (`hiDuel`: Berge/Bauwerke, `HEV` Ereignisse, `HPOP`/`HARE` Länder (ungefähre Werte!), Entfernung von München, `PEOPLE` Lebensalter) mit Mindestabstand der Werte (`hiPair`). Lokal reihum, online parallel (`hiPar`); richtig = +1 (`hiOk`), kein Timer-Wert = falsch. `HNS` enthält jetzt auch `m`, `t`, `h`.
- **Tastatur (iPad mit Magic Keyboard, Mac, PC):** Ein globaler `keydown`-Handler (Abschnitt "Tastatur", vor der Diagnose) löst nur **dieselben Klick-/Zeiger-Ereignisse** wie die Fingerbedienung aus (`el.click()`, synthetische `PointerEvent`s) – dadurch laufen Tasten auch auf Mitspieler-Geräten über die normale Weiterleitung an den Host. `kbPrep()` (aus `scr()` und `netClientData`) macht klickbare Nicht-Knöpfe (`[onclick]`/`[data-h-click]`: Chips, Schalter, Karten) per `tabindex`/`role=button` fokussierbar. Belegung: Ziffern = n-ter `.opt`/Ort bzw. Spiel auf der Startseite (4 Gewinnt: 1–7 Spalte, ←/→ markiert, ↓/Enter wirft), Leertaste/Enter = Reflex tippen (`kbRx`), Enter/Leertaste = Haupt-Knopf (`kbPrimary`: erster `.ok`, sonst letzter Knopf ohne `sec|ib|qm|opt|back|gt|sg|lo`), ←/→ = Wellenlänge-Marker (Shift = 5), `I` Info, `S` Überspringen, `T` Tabu, `Esc` Hauptmenü-Rückfrage (Fokus auf "Weiter spielen"). In Eingabefeldern gelten nur Enter (Namensliste, Online-Felder) und Esc. **Neue Spiele:** Auswahlknöpfe als `.opt` bauen, dann funktionieren die Ziffern automatisch; neue Haupt-Knöpfe ohne `sec`-Klasse; neue Tastenkürzel in Einstellungen → "Tastatur" ergänzen.
- **Startseite mit Kategorien:** `CATS` (Quiz, Party, Gruppe, Knobeln & Duell, Action & Reflex, Trinken) und `GCAT` (Spiel → Kategorie, wird als `GAMES[id].cat` gesetzt). `home()` ("Startseite 2.0"): flacher Umschalter Ein Gerät/Online, kompakte Spielerleiste (`.pbar`, überlappende Avatare), Zufallsspiel-Banner (`.rnd`), darunter je Kategorie ein Header mit farbigem Icon (`.sech`, Tippen = nur diese Kategorie, `HCAT`, gemerkt in `pb_cat`) und eine seitlich wischbare Kartenreihe (`.rowh`, ab 700 px ein Raster); Spiele mit mehr nötigen Spielern als vorhanden sind ausgegraut (`.gt.dim`), `randomGame()` = Zufall (in "Alle" nie ein Trinkspiel). Kategorie-Farben stehen in `CATS[].c`. **Neues Spiel:** in `GCAT` eintragen, sonst fehlt es auf der Startseite.
- **Trinkspiele (ab 18):** Kategorie `drink` (`never` = Ich hab noch nie, `kings` = Königsrunde) und optionale **Trink-Variante** für Arschkarte, Bluff, Wer würde am ehesten, Heiße Bombe, Reflex (`DRKV`, `OPT[id].drink`, Chip im Setup über `drinkChip`; Ergebnisse zeigen `drinkBox`). Vor dem ersten Trinkspiel/der ersten Variante erscheint einmalig der Hinweis `drinkGate` (ab 18, **alkoholfrei geht genauso**, nicht verpflichtend; gemerkt in `pb_dnote`). Zwei getrennte Schalter (Einstellungen → "Trinkspiele (ab 18)"): `C.drink` = Kategorie/Spiele `never`/`kings` anzeigen, `C.sips` = Funktion „Schlucke verteilen" (Trink-Variante, `sipsOn()`; aus setzt `OPT[g].drink=false` und `drinkChip` entfällt). Schlucke sind immer nur **Vorschläge**; keine Regeln, die zu großen Mengen auffordern (Wasserfall, Exen o. Ä.) einbauen. `never`: Aussagen `NV`, lokal reihum geheim, online parallel (`nePar`), Wertung = Schlucke (weniger ist besser, `finish({asc:true})`). `kings`: Karten `KR`/`KS`, öffentliche Screens `kiTurn`/`kiShow` mit `PERMS` = Spieler am Zug, Abschluss `kiEnd` (kein `finish`, keine Statistik).
- **Klassiker (Block "Klassiker" vor dem Trink-Block):** `memo` Memory (min 1, `mmScreen`/`mmFlip`, allein Wertung in Zügen), `hang` Galgenmännchen (min 1, Wörter `HGW`, nur A–Z, Namespace `g`; Treffer +1 je Vorkommen, Wort lösen +3, 8 Fehler = verloren; `hgScreen`/`hgGuess`), `code` Codeknacker (min 1, 4 Farben, 10 Versuche, `ckEval`; Reihum mit `hand`, Wertung = Versuche, nicht geknackt = 11, `finish({asc:true})`), `ttt` Drei gewinnt (min 1, allein/zu zweit gegen Computer `ttBest` per Minimax; Muster wie 4 Gewinnt mit `G.pi`), `dots` Käsekästchen (min 2, `dsEdge`, Kästchen schließen = nochmal), `bs` Schiffe versenken (min 1; 8×8 mit 4 oder 10×10 mit 5 Schiffen, Option „Nach Treffer nochmal“, Best of; Flotten platziert jeder privat nach `hand` über `bsPlace`/`bsPut` (Startfeld + Richtung, Zufällig, Zurück), danach öffentlicher Schussbildschirm `bsTurn` (PUBW, Recht = Schütze, zeigt nur Treffer/Wasser, nie Schiffe); Computer `bsCpuPick` (leicht zufällig, schwer jagt Treffer mit Paritätssuche); wie `ttt` mit `G.pi`/CPU = -1), `slf` Stadt, Land, Fluss (min 2, mit Zettel & Stift: App gibt Buchstaben/Timer vor, Punkte trägt der Host per +/− in 5er-Schritten ein, `slfAdj`/`slfCommit`). `slf` hat zwei Spielweisen (`OPT.slf.mode`): `zettel` (siehe oben) und `digital` (Wörter eintippen): lokal reihum mit `hand` (`slfDType`, Zeit `dtimer`), online parallel (`slfDPar`, ein Schritt `w`, Felder `c0…c4`, `autoSub` schickt bei Zeitablauf auch Teilantworten); Auswertung automatisch in `slfCalc` (10 eigen / 5 gleich / 20 allein, Wort muss mit dem Buchstaben beginnen, Vergleich über `norm`), danach `slfReview` (PUBW, nur der Host streicht per Tipp falsche Wörter, `G.bad`). **Kategorien frei wählbar:** `SLFA` (17 Vorschläge) als Chips plus bis zu 4 eigene (`OPT.slf.sel`/`custom`, gemerkt in `pb_slfc`, 3–10 insgesamt, bei <3 Rückfall auf Stadt/Land/Fluss/Tier/Beruf); `slfStart` legt `G.cats` fest, alle Screens und die Auswertung nutzen `G.cats`; eigene Namen immer mit `esc`. Inhalte (echte Stadt/Fluss …) werden **nicht** geprüft, das entscheiden die Spieler. Alle sind rein öffentliche Brettspiele mit **Recht für den Spieler am Zug** (`PERMS`: `mmScreen`, `hgScreen`, `ttScreen`, `dsScreen`) und rendern jeden Zustand über die (in `PUBW` eingetragene) Screen-Funktion neu; nur `code` ist privat (`hand` → `ckScreen`, Ergebnis `ckResult` in `PUBW`). Verzögerte Aktionen (Memory-Umdrehen, CPU-Zug, Ende) prüfen `G===g`. Kategorie `brain` = Knobeln & Duell (Memo/Hang/Code/4 Gewinnt/ttt/dots), `party` enthält `slf`. Buttons im Raster tragen Klasse `kx` (nicht Haupt-Knopf für Enter), Zahlen-Tasten wählen `[data-kn]` (ttt-Felder 1–9, Codeknacker-Farben 1–6); `Backspace` = Codeknacker löschen, Buchstabentasten = Galgenmännchen (`#hg`). `recordStats` nutzt `G.pi`, wenn gesetzt.
- **Hauptmenü-Knopf:** `#hm` (oben links, `body.live`) erscheint nur während eines laufenden Spiels (`setLive(true)` in `startSession`, `setLive(false)` in `home`, `gameSetup`, `settings`, `playersScreen`, `statsScreen`, `lobbyScreen`, `onlineMenu`, `joinScreen`, `finish`; neue Menü-Screens dort ebenfalls eintragen). Mit Rückfrage (`hmAsk`) → `home()`; auf Client-Geräten (Klasse `live` ab Beitritt) erscheint er ebenfalls, dort heißt der Dialog "Lobby verlassen" und ruft `netLeave()`; beim Host beendet er das Spiel für alle. Die Anzeige oben rechts (`#lv`, Code · Name) ist nur Info, nicht klickbar.
- **Arschkarte zu zweit:** `G.tip=S.P.length>2`; ohne Tippen (nur 2 Spieler, die Wahl wäre erzwungen) entfallen Tipp-Bildschirm/-Schritt, Tipp-Zeilen und die Tippzeit (`arAfter`, `arPar` mit einem Schritt). **4 Gewinnt** hat `min:1`: mit einem Spieler (`S.names.length<2`) ist der Gegner immer der Computer; die Spielerliste geht bis 1 herunter (andere Spiele sperren per `pickGame`).
- **Arschkarte-Kategorien:** `QCATS` (Wissen, Jahreszahlen, Rechnen & Orte, Lustig & Alltag, Essen & Trinken, Tiere & Natur); feste Fragen je Kategorie in `QPOOL` (`Q` aufgeteilt in Wissen/Jahreszahlen, neue Kategorien in `QX`), generierte in `QGEN`. `OPT.arsch.cats` (nichts gewählt = alle), `buildDeck` mischt feste und generierte Fragen (je Hälfte, falls beides da ist) und liefert bei kleinen Kategorien ein kürzeres Deck; `arStart` kürzt dann `G.rounds`. Neue Fragen: `[Text, Zahl ≠ 0, Einheit]`, bei Näherungswerten "ungefähr" bzw. die Rechengrundlage in die Frage schreiben, keine doppelten Texte.
- **Timer:** Anzeige `#tmr` (oben mittig) per `tmrShow(ms,onEnd)`/`tmrHide()` (`stopAll()` blendet sie aus). Lokal (Arschkarte, `OPT.arsch.timer`, 0 = aus, Standard 30 s): `arGuess` startet ihn, bei Ablauf zählt eine getippte Zahl (`arTimeUp`), sonst `null` = keine Antwort (in `arResult` ohne Punkte, aus Best/Worst herausgerechnet). Online: `parBegin({dur:[ms,…]})` = Zeitphasen pro Schritt (Schätzen, danach `ARTIP_MS` zum Tippen); der Host schließt eine Phase 1,5 s nach Ablauf (`parTick`, `step.timeout(pi)` setzt Standardwerte), die Clients bekommen Paket `tm` (Restzeit, kein Datum → keine Uhrenabweichung) und schicken bei 0 den getippten Wert automatisch ab (`autoSub`). `parEnd()` beendet alles und schickt `tm {off}`.
- **Statistik:** nur pro Gerät, `localStorage` `pb_stats` (Schlüssel `n:<name klein>`, je Spiel `{n,w,p,s:{Zähler},m:{Minima}}`), keine IP/kein Server. `recordStats` in `finish()` (Einzel- und Teamspiele, bei 4 Gewinnt über `G.pi`, CPU wird ignoriert); Online speichert der Host alle Namen und schickt jedem Client Paket `stat`, das dessen Gerät unter `NET.name` speichert. Zusatzwerte je Spiel in `statExtra` (Arschkarte: Arschkarten/nächste, Reflex: beste ms). Anzeige `statsScreen()` (📊 auf der Startseite, nur wenn nicht online).
- Pointer-Interaktionen (Balken, Brett) brauchen `data-ptr` am Element; Positionen laufen normiert (`rx`, `ry`).
- Verbindung: Lobby-Code 5 Zeichen (`APP_CODE_LEN`), Host-Peer-ID `pbox-CODE`, Heartbeat alle 4 s, Timeout 16 s. Getrennte Spieler bleiben in `NET.m`, ihr Gerät fällt auf den Host zurück (`devIdx`); Identität eines Geräts = Geräte-ID (`pb_cid` in localStorage, wird in `hi` mitgeschickt): gleiche ID übernimmt den Platz, auch wenn die alte Verbindung noch offen wirkt; gleicher Name mit anderer ID wird "Name 2"; alte Clients ohne ID: Übernahme per Name nur bei getrennter Verbindung. **Neuladen/App-Neustart (Client):** die Sitzung (`pb_sess`: Code, Name, max. 3 h) wird beim Beitritt gemerkt und beim Start automatisch wieder aufgebaut; vergessen wird sie bei bewusstem Verlassen, `bye` (Lobby geschlossen/voll) und fehlgeschlagenem Beitritt. Der **Host** kann nach Neuladen nicht wiederhergestellt werden (Spielzustand liegt nur im Speicher). Max. 10 Spieler. Wake Lock auf dem Host.
- Link-Beitritt: `index.html#CODE`.
- **PWA / Offline:** `manifest.webmanifest` (standalone, Icons), `sw.js` (Service Worker, Cache `pbox-v1`): **Netzwerk zuerst** (5 s Timeout), bei fehlendem Netz aus dem Cache – so kommt jede neue Version sofort an, und die lokalen Spiele laufen offline. ## Bekannte Grenzen

- Reflex online: Zeit wird auf dem Gerät des Spielers gemessen, ist aber nicht manipulationssicher (Grenzen siehe oben). Die Verzögerung vom Host zum Handy (bis Grün erscheint) bleibt unberücksichtigt.
- Reihum statt parallel laufen online noch Pantomime, Wellenlänge, Reflex, Bombe (inhaltlich Reihum) – Arschkarte, Bluff, Spion sind parallel.
- TURN: Die eingebettete PeerJS-Version bringt Standard-ICE-Server mit (Google-STUN plus die öffentlichen PeerJS-TURN-Server `turn:eu-0/us-0.turn.peerjs.com`, Zugang `peerjs`/`peerjsp`); `new Peer(id,{debug:0})` übernimmt sie. Mobilfunk (CGNAT) sollte damit über den Relay laufen, ist aber **nicht über echtes Mobilfunknetz getestet**, und der kostenlose öffentliche TURN ist Best-Effort. Eigene TURN-Zugangsdaten (z. B. Cloudflare/Metered) wären nötig, wenn es dennoch scheitert – sie lägen im öffentlichen Quelltext.
- Host muss die App offen lassen.

## Ideen für später (NICHT umsetzen, nur festgehalten)

**Anzeige-Bildschirm + mehrere Handys als Mitspieler** (Idee von Sascha, Annahme: so gemeint)
- Heute: Das Host-Gerät ist Spiel *und* Spieler. Wenn der Host selbst dran ist, verdeckt sein privates Formular (`#hw`-Overlay) den gemeinsamen Bildschirm; der Host kann also nicht gleichzeitig mitspielen und den öffentlichen Stand sehen.
- Idee: Das Host-Gerät (z. B. iPad oder Laptop) zeigt dauerhaft nur den **gemeinsamen Anzeige-Bildschirm** (Status, Ergebnisse, Brett, Rangliste) als Overlay über allem. Alle Spieler, **auch der Host als Person**, spielen mit ihrem eigenen Handy als normaler Client (privater Screen wie bei den parallelen Eingaben). So kann der Host genauso mitspielen wie jeder andere.
- Mögliche Bausteine: eigene Rolle "Anzeige" in `NET.m` (kein Spielerindex), Host-Person als zusätzlicher Client-Spieler, Steuerrecht für öffentliche Screens ("Nächste Frage", Rundenstart) für den Host-Spieler oder alle statt nur das Host-Gerät, Reihum-Spiele zeigen "Gerade dran" auf der Anzeige. Die Mechanik `own`/`parSub` und `PERMS` sind dafür schon die Grundlage.
- Offen: ob die Anzeige auch ohne Mitspieler-Slot laufen soll, und wie der Host-Spieler ohne zweites Gerät spielt (zweiter Browser-Tab auf demselben Gerät?).
